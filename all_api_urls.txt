MODULE 3: TWO-FACTOR AUTHENTICATION (2FA - TOTP) (6 ENDPOINTS)
--------------------------------------------------------------------------------

13. GET  /api/v1/auth/2fa/status
    --> Used for checking if 2FA (Time-based One-Time Password) is currently enabled for the user.
    - Access: Authenticated (Requires Bearer token or HttpOnly Cookie)
    - Response: ApiResponse<TwoFactorStatusDto> (isEnabled: boolean, backupCodesRemaining: number)

14. POST /api/v1/auth/2fa/setup
    --> Used for initiating 2FA setup; generates a shared TOTP secret and QR code URI.
    - Access: Authenticated (Requires Bearer token or HttpOnly Cookie)
    - Response: ApiResponse<TwoFactorSetupResponseDto> (secretKey, qrCodeUri, backupCodes)

15. POST /api/v1/auth/2fa/enable
    --> Used for confirming 2FA setup by verifying a valid 6-digit TOTP code from authenticator app.
    - Access: Authenticated (Requires Bearer token or HttpOnly Cookie)
    - Request Body:
      {
        "code": "123456"
      }
    - Response: ApiResponse<Void>

16. POST /api/v1/auth/2fa/verify
    --> Used during login challenge to verify a TOTP code or 8-character backup code.
    - Access: Authenticated / Session Token
    - Request Body:
      {
        "code": "123456"
      }
    - Response: ApiResponse<TwoFactorVerifyResponseDto> (verified: true)

17. POST /api/v1/auth/2fa/disable
    --> Used for disabling 2FA on the user's account after confirming with current TOTP code or password.
    - Access: Authenticated (Requires Bearer token or HttpOnly Cookie)
    - Request Body:
      {
        "code": "123456"
      }
    - Response: ApiResponse<Void>

18. POST /api/v1/auth/2fa/regenerate-backup-codes
    --> Used for regenerating a new set of emergency recovery/backup codes.
    - Access: Authenticated (Requires Bearer token or HttpOnly Cookie)
    - Response: ApiResponse<List<String>> (List of 8 single-use backup codes)

20. GET /api/v1/mosques/nearby
    --> Used for PostGIS geospatial radius discovery: finds closest mosques from GPS coordinates.
    - Access: Public (No authentication required)
    - Query Parameters:
      - latitude: float [-90.0 to 90.0] (Required, e.g. 51.5173)
      - longitude: float [-180.0 to 180.0] (Required, e.g. -0.0658)
      - radiusKm: float (Optional, default: 10.0)
      - facilities: comma-separated codes (Optional, e.g. 'WOMENS_SECTION,PARKING')
    - Response: ApiResponse<List<MosqueSummaryDto>> sorted by distance in kilometers

21. GET /api/v1/mosques
    --> Used for paginated keyword, city, and country search across the global mosque directory.
    - Access: Public (No authentication required)
    - Aliases:
      - GET /api/v1/mosques/search
      - GET /api/v1/mosques/
    - Query Parameters:
      - q: string (Optional keyword matching name or address)
      - city: string (Optional city filter, e.g. 'London')
      - country: string (Optional country filter, e.g. 'United Kingdom')
      - page: integer (Optional, 0-indexed, default: 0)
      - size: integer (Optional, default: 20)
    - Response: ApiResponse<PageResponse<MosqueSummaryDto>>

22. GET /api/v1/mosques/{idOrSlug}
    --> Used for retrieving a mosque's complete profile by UUID or unique URL slug.
    - Access: Public (No authentication required)
    - Path Variable: idOrSlug (UUID e.g. '18558e48-...' or Slug e.g. 'east-london-mosque-london')
    - Response: ApiResponse<MosqueResponseDto> (details, coordinates, contact, photos, facilities, liveStreamUrl)

23. PUT /api/v1/mosques/{id}
    --> Used by approved Mosque Administrators or Super Admins to update an existing mosque profile.
    - Access: Mosque Admin / Super Admin (Requires MOSQUE_ADMIN or SUPER_ADMIN role)
    - Path Variable: id (Mosque UUID)
    - Request Body: MosqueUpdateRequestDto (name, description, contactPhone, websiteUrl, liveStreamUrl, facilityCodes, imageUrls)
    - Response: ApiResponse<MosqueResponseDto>
